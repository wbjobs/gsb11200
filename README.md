# CRDT 实时协同看板

多标签页实时协同看板：支持 4+ 标签页实时同步，卡片可拖拽排序、跨列移动、编辑、删除；
离线可用，恢复后自动合并。零依赖、纯前端实现。

## 运行

```bash
npm start          # 或: python3 -m http.server 8000
# 打开 http://localhost:8000 ，点「打开新标签页」开多个标签页测试
```

## 测试

```bash
npm test           # CRDT 核心单测(10) + 同步层集成测试(7)，全部通过
```

## 技术架构

| 层 | 文件 | 说明 |
|---|---|---|
| HLC 混合逻辑时钟 | `js/hlc.js` | 为每个操作生成全局全序时间戳 `{t,c,n}` |
| Logoot 位置 | `js/logoot.js` | 分数位置标识符，任意两位置间可插入，并发排序收敛 |
| CRDT 核心 | `js/crdt-store.js` | 操作日志 + 物化状态，全部操作可交换、幂等 |
| 持久化 | `js/db.js` | IndexedDB 操作日志，刷新/关闭不丢数据 |
| 同步 | `js/sync.js` | BroadcastChannel 广播 + 版本向量反熵 + 共享存储兜底 |
| UI | `js/app.js` | Pointer Events 拖拽、编辑、渲染 |

## 冲突处理规则

- **拖拽冲突**（两标签页拖同一卡片）：移动是 LWW 寄存器，HLC 全序最新者胜，最终一致
- **排序冲突**（并发插入同一位置）：Logoot 位置全局唯一且全序，任意顺序合并结果一致
- **删除冲突**（删除 vs 编辑/移动）：删除优先（delete-wins 墓碑），删除后的编辑/移动被忽略，不可复活
- **离线合并**：操作先写 IndexedDB 再广播；恢复在线后通过版本向量反熵双向补齐
- **消息乱序**：操作幂等去重（`author:seq`），应用逻辑与到达顺序无关（可交换）
- **标签页关闭**：心跳 6s 未达即移除在线名单；其操作已持久化，其他标签页通过
  共享 IndexedDB 轮询兜底捡回「离线操作后关闭」的操作

## 验收标准对照

| 标准 | 实现 | 验证 |
|---|---|---|
| 两标签页拖同一卡片最终一致 | MOVE LWW + HLC 全序 | `test/crdt.test.js` / `test/sync.test.js` 对应用例 |
| 离线操作恢复后合并正确 | 版本向量反熵 + 共享 IDB 兜底 | 同上 |
| 4 标签页同步延迟 < 200ms | BroadcastChannel 即时广播（实测 ~5ms） | 集成测试断言 + 页面状态栏实时显示 |
| 删除与编辑冲突正确解决 | delete-wins 墓碑 | 对应用例 |
| 消息乱序不丢操作 | 操作幂等去重 + 可交换应用 | 乱序对应用例 |
| 刷新不丢数据 | 操作先写 IndexedDB，启动时重建 | 重开恢复对应用例 |

## 手动验收建议

1. 开 4 个标签页，任一处增删改/拖拽，其余 200ms 内跟随（状态栏显示实测延迟）
2. 两个标签页同时拖同一张卡到不同列，松手后两边最终一致
3. 点「模拟离线」，做若干增删改拖，点「恢复在线」，全部自动合并
4. 一个标签页删除卡片的同时另一个在编辑它：删除生效，编辑被忽略
5. 刷新任意标签页，数据完整保留
