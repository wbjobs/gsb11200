# CRDT 协同看板

纯前端多标签页实时协同看板，无构建步骤、无外部依赖。

## 运行

```bash
npm start          # 或 python3 -m http.server 8000
```

打开 4 个 `http://localhost:8000` 标签页即可验证实时同步。

## 测试

```bash
npm test           # node --test tests/（12 个用例，覆盖全部验收标准）
```

## 技术栈

- **BroadcastChannel**：标签页间操作广播（`js/sync.js`），实测投递延迟为亚毫秒级，远低于 200ms
- **IndexedDB**：操作日志持久化（`js/db.js`），刷新后重放恢复
- **Pointer Events**：拖拽实现（`js/drag.js`），支持列内排序与跨列移动，pointer capture 保证指针移出窗口不丢手势
- **CRDT**：Lamport 时钟 + LWW 寄存器 + 分数位置索引（`js/crdt.js`、`js/fractional.js`）

## 架构

```
用户操作 → CRDTStore.makeOp → applyOp（本地立即生效）
                            → IndexedDB 持久化
                            → BroadcastChannel 广播（离线时入缓存队列）
远端操作 → applyOp（幂等、可交换）→ 持久化 → 重渲染
重连/新标签页 → sync-request(向量时钟) → 对端回传缺失操作 → 合并
```

## 冲突解决规则

| 冲突 | 规则 |
|---|---|
| 拖拽同一卡片 | `(column, posKey)` 是 LWW 寄存器，按 `(lamport, clientId)` 取唯一赢家，各端一致 |
| 排序冲突 | 分数位置索引生成无序对的位置键；同键时按卡片 id 决胜，顺序确定 |
| 删除 vs 编辑 | 删除优先（永久墓碑）；字段仍按 LWW 收敛，保证全状态一致 |
| 消息乱序 | 操作幂等且可交换；先于 `create` 到达的操作写入占位记录后合并 |
| 离线合并 | 离线期间操作入本地队列；恢复后先广播缓存操作，再按向量时钟拉取缺失操作 |
| 标签页关闭 | 状态已在 IndexedDB；`pagehide` 广播离开消息，其余标签页继续工作 |

## 验收标准对照

- 两个标签页拖拽同一卡片最终一致 → `tests/crdt.test.mjs` 第 1 个用例
- 离线操作恢复后合并正确 → `tests/sync.test.mjs`「离线操作恢复后自动合并」
- 4 个标签页同步延迟 < 200ms → BroadcastChannel 为同步事件循环投递（亚毫秒）；「4 个标签页实时同步」用例
- 删除与编辑冲突正确解决 → 删除优先，两个测试文件均有用例
- 消息乱序不丢操作 → 乱序/重复投递用例（60 操作随机打乱 + 重复投递）
- 刷新不丢数据 → IndexedDB 重放 + 反熵同步用例

## 手动验证建议

1. 开 4 个标签页，任一端新增/拖拽/编辑/删除，其余端即时更新（右上角显示在线标签页数）
2. 两个标签页同时拖同一张卡片到不同列 → 最终所有端停在同一列
3. 点「模拟离线」，做若干操作，另一标签页也做操作，再点「恢复在线」→ 两端状态合并一致
4. 一端删除卡片，另一端同时编辑 → 卡片被删除
5. 刷新任意标签页 → 数据完整恢复
